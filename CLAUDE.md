the spec names a membership, a claim and a dependency by other params than their ids, so `membershipOf`, `claimOf`, `activeClaimOf` and `dependencyOf` find them, and with no such record give the permission failure the policies would, then the content check). The lease reaches the actions as `context.leaseMs` (gap G34; the context factory puts it on every context, the engine's a frozen copy of `ENGINE`), which `leaseEnd` in `work.helpers.ts` reads, `LEASE_MS` when absent. A claim whose `expiresAt` has passed is expired for every check before the sweeper marks it (PROTOCOL.md:312): `liveClaims`, the revoke check (`!&lapsed`), renew and release (`claim.expired`, also for a claim marked expired whatever the clock reads) and the effects that revoke claims (cancel, assign, unassign, membership revoke, collaborator retire) skip it and leave it to the sweeper, where Hyper's `revoke_all` revokes it. A command function reads no clock of its own: it judges a lease through Claim's `lapsed`, loaded inside its transaction, so at the transaction's instant (ACT-29), the one its actions check (`staleClaimWithLapsed` for the late result of `taskComplete` and `submissionSubmit`). Command results re-read the Task (`currentTask`), since an effect touches it after the action wrote its row; in-process method tests (`test/rpc-methods.test.ts`) set the world's clock to the system's, because the methods show a Task's `activeClaim` at the system's time; `test/daemon.test.ts` spawns it. `conformance/` holds copies from the Hyper specification at commit `ccc00f9` (the harness, `schemas/protocol.ts`, and under `cases/` only the cases the daemon passes; `conformance/README.md` lists every file and what each edited copy removed). Those copies are the gate (RDM-02) and are never synced back: the spec repository will be deleted. `bun run conformance` (`scripts/conformance.ts`, a `verify` step) runs `bun test` over `conformance/cases` against `main.ts` and fails unless the cases it finds are exactly those in `conformance/cases.txt` and every one passes (a missing, skipped, failing or unlisted case fails it); a PR that makes a case pass copies it in unedited and adds its line. The package's `test` script runs `bun test ./test`, so it never picks up the copies, and `typecheck` also runs `tsc --noEmit -p conformance` (the spec's compiler options); `@sinclair/typebox` (exact `0.34.52`) is a dev dependency only for them.
- `examples/blog` (`blog-example`, private): entity files under `src/domain/blog/`, committed output under `.mesh/` (the adapter's `schema.ts`, `binding.ts`, and `index.ts`, which `#mesh` maps to; the domain root's barrel `.mesh/domain/index.ts`, which `#mesh/domain` maps to and which exports the `blog` namespace; the entity files and the module's `index.ts`, which `#mesh/domain/blog` maps to, under `.mesh/domain/blog/`); `src/context.ts` declares a required `actor`; `bun run db:push` then `bun run start` runs `src/main.ts` against the gitignored `blog.db`; `bun run test` is `mesh build --check && bun test` (`test/blog.test.ts` binds `:memory:`; its connect tests run in a temporary working directory so `blog.db` is untouched)
- `tsconfig.base.json`: shared strict config that packages extend (root `tsconfig.json` covers `scripts/`); `scripts/verify.ts`: the `verify` runner

## Commands

- MX is a separate project, published on `https://npm.saulo.tech`; the root `bunfig.toml` scopes `@mxlang` to that registry and `packages/compiler` depends on `@mxlang/core` by exact version (currently `0.1.0-alpha.26`; `@mxlang/data` no longer exists and `@meshfw/compiler`'s `package.json` has no `mx` key; `@mxlang/tree-sitter-mx` stays at `0.1.0-alpha.2`). `lowerSource` returns `{ ir, diagnostics }` (IR version 4, `ir` undefined on any error, never throws). A tag is a `DelegatedTag` node; an attribute is `static` (string, atom or member, told apart by `atom` and `member`), `boolean`, `dynamic`, `bound` or `spread`; a tagless member line is a `member` tag with `trigger.id === "member"`. Imports are `ir.imports` (`from`, `names`, name `span`/`localSpan`). `src/front-end/dialect.ts` builds `MESH_DIALECT` from Mesh's own syntax rows in `src/front-end/syntax/` (`atoms-sugars.ts`, `member.ts`, `mesh.ts`, ported from MX's reference module at MX commit `750c80ec1`; MX deletes its copies after Mesh sends DONE; Mesh owns all of its syntax; `transaction.ts`, the `%.name` row of SYN-29, is Mesh's own, modelled on the `&name` row as the MX lead advised, with no new MX alpha): id `mesh`, name `Mesh`, `tagRules: "none"`, no `#id`/`.class` rows. The dialect also carries Mesh's vocabulary and its strictness (since MX alpha.21): `contracts: MESH_CONTRACTS` (`Dialect.contracts` is `@unstable` in MX), `structural: "reject"`, `unknownTags: "reject"`, `imports: "pass"`. A caller of `lowerSource` passes the dialect and nothing else, never `customTags` (a passed `customTags` overrides the dialect's `contracts` silently) and no strictness option, so the editor checks a Mesh file exactly as the CLI does. Build `MESH_DIALECT` once and freeze it: MX re-validates an unfrozen dialect object on every call (about 46 ms instead of 3 ms). A test of the syntax alone uses `SYNTAX_DIALECT` (`test/syntax-dialect.ts`), the dialect without contracts or strictness. The syntax files import only the public `@mxlang/core` API, and `test/no-core-syntax-import.test.ts` fails on any import of `@mxlang/core/syntax` in `packages/` or `examples/`. The value row `atom-value` and the `Atom` node type name the dialect, so the id must stay `mesh`; a whole-value atom (`inverse=:owner`) lowers to the same atom-marked `static` attribute as an atom elsewhere (`Attr.node` stays unset). The atom contract checks are Mesh's (`atomsHooks.afterLower` in `syntax/atoms-sugars.ts`) and see value atoms (`test/atom-values.test.ts`); since alpha.17 core has no name sugar or atom lexing (`:x` in a `.mx` file is plain JavaScript; a dialect row returns a `StringLiteral` marked `extra.mxAtom`) and ships no dialect: a colon in a tag head is part of the tag name (`uuid:id`, `<string:title/>`, `entity:Todo`, `<:x/>` are unknown tags to MX), and an `afterLower` hook sees only the tags a contract names, so the dialect's `explainUnknownTag` hook (`front-end/dialect.ts`; `@unstable` in MX) refuses a name with a `:` as `MESH_UNSPACED_NAME`, replacing MX's own unknown-tag error for it (one lowering; the `:x` wording reads the parent contract's `defaultTag` from the hook's ancestors). Core no longer checks the atom contract keys: `values`, `pattern`, `ref` and `declares` are claimed by Mesh's `contractFields` and checked in its `checkContract`/`afterLower`. `run [after=:write] (...) {}` lowers to one `value`; a real duplicate warns with code `MX_DUPLICATE_ATTRIBUTE`. Match diagnostics by `code`, never by message text: MX's codes are `MX_UNKNOWN_TAG`, `MX_TAG_NOT_ALLOWED`, `MX_TEXT_NOT_ALLOWED`, `MX_EXPECTED_SINGLE_EXPRESSION`, `MX_DUPLICATE_ATTRIBUTE`; Mesh's own come through `ctx.fail(message, { at, code: "MESH_X" })` (never a `MESH_X: ` message prefix), and `buildModel` keeps every code MX gives (`MX_*` or `MESH_*`; since alpha.23 every MX error and warning has one), so the build's diagnostics carry `MX_UNKNOWN_TAG` as the editor shows it (`mesh build` prints each one: `file:line:column severity CODE message`, from `formatDiagnostic` in `@meshfw/model`); `meshDiagnostic` maps a diagnostic with no code to `MESH_SYNTAX` (a fallback no `.mesh.mx` source reaches). The CLI prints every line with its code, `MX_*` as MX gives it; a diagnostic with no code prints without one. Under `unknownTags: "reject"` an unknown tag in a closed parent gives only `MX_UNKNOWN_TAG`; the by-text pair filter is gone. An unnamed tag in a closed parent takes the nearest parent contract's `defaultTag`, so `<set><#a/></set>` gives one error. A spaced `#id`/`.class` is Marko's "Invalid attribute name"; `<x=1 :n=2/>` is Marko's "Expected a single expression, but found `:` after it." (`MX_EXPECTED_SINGLE_EXPRESSION`). Members are read from those shapes only, never from `Expr.code` (printed `self.x`); authored text is the source sliced at `Expr.span`. `meshfw`'s package.json declares `mx.dialect` (`id: "mesh"`, `extensions` equal to `MESH_EXTENSIONS`, `module: "./dist/dialect.js"`); `bun run build` in `packages/cli` (`scripts/build-dialect.ts`, part of `verify`) bundles `src/dialect.ts` into that plain-JavaScript file, fails when the manifest drifts from `MESH_EXTENSIONS`, and `packages/cli/dist/` is gitignored. `prepare` runs the same build, so `bun install` and `bun pm pack` produce `dist/`. ## Rules

- The user-facing CLI package is `meshfw` (binary `mesh`; it re-exports `defineConfig`, but projects import `defineConfig` from `@meshfw/runtime`); the starter is `create-meshfw` (`bun create meshfw todo-app`). Other framework packages remain `@meshfw/*`. These are the workspace package names and the documented 1.0 naming. User docs write `mesh build` and other `mesh` commands; Quick start alone explains the `bunx mesh build` local-binary alternative.
- User docs separate `configuration.md` (project/context/adapters/environment) from `command-line.md` (commands/flags/exit codes). `using-your-domain.md` replaces the old Calling actions page. Framework integration snippets are explicitly `(excerpt)` fences; the sample checker counts exclusions dynamically rather than claiming they compile.
- `plugins/mx-figure.js` also injects site title/heading CSS and strips paired code backticks from docmd's known plain-text title labels at build time. It must not rewrite authored code blocks, URLs or escaping. `apps/docs/test/browser/docs-structure.mjs` checks the sidebar/home link, heading scale and title labels in both themes; it needs `SHOTS_DIR`, `SITE_DIR` and `PLAYWRIGHT_MODULE` (Playwright Docker), separately from `verify`.
- `typescript` and `@types/bun` are declared only in the root `package.json`; packages do not repeat them.
- Use bun, never npm.
- Always write "Mesh" (never "Mash").
- Architecture docs hold what cannot be understood from a single code file.
- The `@mxlang` scope resolves from `https://npm.saulo.tech`, the operator's read-only npm registry (no uplink);
  `bunfig.toml` points only that scope at it. `@mxlang/tree-sitter-mx` is what the docs site highlights `mx`
  with; a docs fix goes in `apps/docs/plugins/mx-highlight.js` (the docmd plugin, the capture-name palette)
  or goes to the MX lead as a grammar gap.
- `apps/docs/plugins/mx-highlight.js` is MX's highlighter's docmd plugin and not ours to fork: the grammar
  and the queries belong to MX. Change the palette only, except for the explicitly approved, tested,
  counted v4 input allowance above and `MESH_V4_MEMBER_RENDER`: a Mesh-side render-only overlay
  that colours operand/bare/sort `&name` heads, and `%.now`/`%.today` where they start an operand (SYN-29,
  widened on the lead's brief), as `ts-member`, leaving literals, comments and infix operators (`a % b`) alone. Both bridges go away with `mesh-syntax-highlighting-route` (MX decision 182
  addendum 1). Do not patch the grammar or broaden either bridge silently.
- Home token explanations live in `apps/docs/plugins/mesh-home-hints.js`, wired by `mesh-home.js`.
  Keep descriptions outside the code so copying and the home-sample hash retain the authored file;
  every token in the fixed excerpt is checked against the commissioned wording. Each note has a shared
  family sentence followed by optional context; inline fragments use `mxHighlighter` at build time
  (TypeScript through its injection grammar), never a browser highlighter. Reference tokens name
  scoped targets for a single dashed SVG connector and outline. Keyboard navigation has one tab stop
  per nonblank line, with Left/Right and Home/End within it. Mutation/resize observers run only while
  a note is open; the panel is re-created after body replacement. Browser interactions and screenshots
  are exercised by `apps/docs/test/browser/home-hints.mjs` in Playwright's Docker image, separately
  from `bun run verify` (see the script header for its environment variables; screenshots default
  under `os.tmpdir()`, not the checkout).
- docmd 0.9.7 reads a raw HTML block until its tags balance, blank lines included, so Markdown (a fence
  above all) inside an open `<div>` is emitted as raw text. Wrap fences in a docmd container (`::: grids`)
  instead, and keep each HTML block self-contained. docmd also hides `<html>` until its theme script runs;
  `plugins/mx-figure.js` adds the `<noscript>` rule that keeps the site readable without JavaScript.
