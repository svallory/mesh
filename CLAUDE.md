# CLAUDE.md

**Mesh** is a Bun-only TypeScript framework. The compiler parses `.mesh.mx` entity file syntax v4 through closed MX contracts into a plain-data entity model. `:name` declares, `&name` refers, and an imported `Name` names another entity. MX lowers `&name` in every position through Mesh's dialect (`packages/compiler/src/front-end/dialect.ts`). The production compiler never rewrites source or executes expressions.

Eight core generators, each a pure typed view rendered through a Jig template that a project can override from `.mesh-generators/`: `types`, `validators` and `actions` write three files per entity, in `<output>/domain/<module>/` (`<output>/domain/` for the domain root; Mesh's own files stay at the top of `<output>`, so no module name collides with them), `expressions` writes `<entity>.expressions.ts` for an entity that has an expression (every expression as one function of a scope: a translated tree printed as a call chain over `@meshfw/runtime`'s `expr`, a plain one as the authored TypeScript; the actions call them through `$expressions[id]($s)`), `load` writes `<output>/load.ts` when some entity has a relationship or a computed field (the load plan, plain data that `loadRows` in `@meshfw/runtime` follows, and one typed function per entity, `loadTaskFields(tx, rows, names)`, re-exported by its module's index; the record type has no relationship or computed member, `<Entity>Loadable` maps what load can attach and `<Entity>With<N>` is the loaded record; M5's `load` step calls these), `binding` writes `<output>/binding.ts` (`bind(layer, options)`, which is `bindDomain` from `@meshfw/runtime` over the root barrel, the type `Binding`, `connect`, `disconnect` and `transaction`), `module` writes a barrel, `<output>/domain/<path>/index.ts`, for every folder that holds an entity or a folder below it that does, and `<output>/domain/index.ts` for the domain root, always (imported as `#mesh/domain/<path>`, or `#mesh/domain`; CMP-17, CMP-18: each entity's value and record type under one name (`export { Task } from "./task.actions"`), its input, filter, sort and load types and its load functions, and one `export * as <name> from "./<folder>/index"` per subfolder barrel, so `domain.sales.billing.Invoice` reaches a nested entity; PRJ-21: the namespace name is the folder name with every character invalid in an identifier replaced by `_` and `_` in front of a leading digit (`namespaceName`), a reserved word stays as it is (`domain.class`); CMP-05: two exports with one name in one barrel (an entity and a folder, two folders that normalise alike, a generated type and a folder) are `MESH_EMIT_NAME` naming the entity by FQN and the folder by its path), and `index` writes `<output>/index.ts` (`#mesh`: re-exports `bind`, `connect`, `disconnect`, `transaction`, `privileged`, the types `Binding` and `Privileged`, and `tables`, and no entity value or entity type); a project's `package.json` maps `#mesh` to `./.mesh/index.ts`, `#mesh/domain` to `./.mesh/domain/index.ts` and `#mesh/domain/*` to `./.mesh/domain/*/index.ts`. Entity values (CMP-16, PRJ-13, PRJ-19; `runtime/src/entity.ts`): each actions file defines `const $entityValue = $entity("work.Task", bindTask, bindTaskReads, ($call) => ({ ... }))` and exports it as `Task`: a frozen null-prototype object with one method per action (`Task.complete(input, context)`; no `Object.prototype` member answers on it, and no action can be named like one: the model refuses every such member name, `toString` and `constructor` included, as `MESH_ATTRIBUTE_NAME`, `BUILTIN_OBJECT_PROPERTY_NAMES` in `front-end/build.ts`) and Mesh's internals under the symbols `ENTITY`, `BIND`, `BIND_READS`, plus `export type Task = $Record`; there are no composed functions (`completeTask`), no `$delegate`, no `<entity>Actions`/`<entity>Reads` and no `$functions`. A method runs on the binding in scope (the innermost `run(fn)` or `transaction` of a `Binding`, kept in the project's async frame: the generated `binding.ts` makes one `AsyncLocalStorage` and passes it to `bindDomain(domain, layer, options, frame)` as an `AsyncFrame`, so the runtime imports nothing from the host (ADR-0025; `WEB_EXCEPTIONS` in `packages/compiler/test/repository-checks.ts` is empty, and the web rule also fails a `types="bun"` reference); `binding.ts` is the only generated file that may import a host module, `node:async_hooks`, and carries `/// <reference types="bun" />` for it), else on the one `connect()` opened, else it rejects with `FrameworkError` "`work.Task#complete` was called while not connected"; each call is counted in flight on its binding, so `disconnect()` waits for it (`settled`), and once `disconnect()` released the connected binding and nothing runs on it, a call left in its scope (a timer, a chained promise) is not connected either. Messages name an action by FQN and member (`blog.Post#published`, PRJ-17, PRJ-18). `bindDomain` refuses two entity values with one FQN and an entity value bound before with another frame (`FrameworkError`). `bind` returns a frozen `Binding` with exactly `run(fn)` and `transaction(fn)`; tests and scripts call entity values inside `binding.run(...)`. Action functions claim no project-wide name (two modules may each have an `Order` with a `create`); the names `checkNames` still keeps unique across modules (`MESH_EMIT_NAME`) are `bind<Entity>`, `bind<Entity>Reads`, the load functions and `#mesh`'s own; two module folders that differ only in letter case are `MESH_EMIT_PATH`; a plain emitter writes `model.json`, and the data adapter's generator writes `schema.ts`. A generated action runs the lifecycle written out phase by phase (M5, [ADR-0053](./apps/docs/docs/architecture/decisions/0053-validate-then-do.md)): enter and cast (`castInput`; a cast failure is reported alone; inside a running transaction it fails that transaction through `failJoined`, at top level it rejects at once and takes no lock), plan (a create is one insert; every update reads the row first with `selectByKeyForUpdate`, a destroy only when a check, step or policy can see it), the pre-check (M8a, ADR-0055, ACT-28, POL-08: `$authorizer(entity, action, specs)` from `@meshfw/runtime`'s `policy.ts`, made per call over the covering policies (`model/policies.ts`: `policiesCovering`, `readsRecord`); `before(layer, scope)` runs every policy check that reads only `actor`, `context` and `input`, once, before `$runAction`, so a denial writes nothing, takes no lock and runs no seam (not even `beforeTransaction`), and inside a running transaction it fails that transaction through `failJoined`; the call's `$context`, `$actor` and `$clock` are declared here), one transaction holding the policy checks that read the record (`self`, a related record, a call to `privileged`, an entity's action or an imported function (POL-21), or plain code the build cannot read: `await $policies.inside($checkScope($s))` right after the locked read, or on a create the new instance before the input, and before `validate`; POL-03: every covering policy must pass, none covering is `ForbiddenError` with an open policy to copy, an unknown `forbid-if` forbids, an unknown `authorize-if` does not authorize, an unknown `when=` fails its policy; coverage is static (`types=`/`actions=`), a covering policy whose `when=` is false does not apply, and when none applies a write is `ForbiddenError` with `reason` `not-applied` naming them (no open-policy hint) and a read gives `[]`; a policy with no `authorize-if`/`forbid-if` is the build error `MESH_POLICY_NO_CHECKS` (POL-16) and fails at run time; a check that throws goes through `reject`, so a nested call's throw fails the transaction; `ForbiddenError` has `entity`, `action`, `policies`, `reason` (`failed`, `not-covered`, `not-applied`) and a frozen plain-data `breakdown` of the checks that ran), then the `validate` checks (`runCheck` collects every failed check into one `InvalidInputError`; an unknown result fails, ADR-0012 D1; ACT-27, ADR-0053 amended 2026-10-11: a check gets `{ self, input }` with `self` the record before the input, the stored row on an update or destroy and on a create the new instance (defaults, `on=` stamps, a filled `uuid`/`string` key, null elsewhere), and no `before`), the member inputs applied (`$changes.x = $record.x = parsed.x` for each one sent, after every check passed), the `do` steps (`set`, `when`, `load`, `run`; `self` with the input applied, `before` the stored row or `null` on a create), the data layer write (on an update that runs a function before it, `checkUnchanged` refuses the write when a call made in that phase changed the row; every generated write is counted with `noteWrite`), the `afterWrite` seam (`$recordWrite(tx, options.seams, {entity, action}, before, after, parsed, context)`, right after `noteWrite`, before the after-write steps; a destroy whose body cannot see the row reads it first with `selectByKeyForUpdate` while `wantsChanges(seams)`, so `before` is never null; the seam gets `before`/`after` as `cloneValue` copies and the change is frozen), the `run [after=:write]` steps (inside the transaction, `self` the stored record, or the deleted row on a destroy; a `when` around one is evaluated before the write; the action then returns the row read again by key) and the loaded result. Composition (M5, CMP-16, TXN-16 to TXN-20): a function of an entity file calls another action as an entity value's method with an explicit context (`Task.touch({ id }, { ...context, system: true })`; the file sees its own entity and the ones it imports, and `<entity>.expressions.ts` imports the entity values its code names from their actions files by relative path, inside each function so an import cycle between entity files builds and runs), and reads with no policy through `privileged(Task).read(input, context?)` (`privileged` in `@meshfw/runtime`, re-exported by `#mesh`, a registered call of arity 1 in entity files like `isSystem`; one member per read action; it runs on the binding in scope, else the connected one, else throws a not-connected `FrameworkError`; it runs `policies: false` through `layer.transaction`, so it joins a running transaction, reads the running action's instant, and passes only the context it is given, which reaches only the computed fields it loads; its argument must be an entity value the file sees, `MESH_PRIVILEGED_ENTITY`). There is no `actions` or `tx` handle, no composer and no `.mesh/composition.ts`. The call frame (`ActionFrame` in `entity.ts`, kept in the project's `AsyncFrame`) carries the running action's transaction and instant; while a step, a check, a `set` or a policy runs it is labelled, so an entity call or privileged read made there returns a read-only view (`readOnlyRecord`), while one made inside an application `run` or `transaction` returns plain results (ACT-09); while a computed field or a read policy is evaluated it is marked, and an entity call or `privileged` read made then (through a helper too) throws a `FrameworkError` naming `computed :<name> of <Entity>` or `policy :<name> of <Entity>` (TXN-18). A call made after its `run` or `transaction` settled is refused (the scope token is cleared when it settles). An entity bound alone (`bind<Entity>` by itself) runs its nested calls on the binding in scope, else the connected one. A nested call joins through the data layer's re-entrant `transaction` (calls joined to one transaction run one at a time, in the order they were made, each queued on its caller's frame; the base conformance suite checks it), gets only the context it passes, and a failed joined call makes the outermost call reject with a `FrameworkError` whose `cause` is the failure, even when caught; after that failure, a later call that joins is refused before it casts or runs (`DataLayer.refuseIfFailed`, called first by `castInput`, which also says whether the call joins a transaction, answering for the caller's async context only; and the join itself; a joined call must never await a call joined after it from the same frame, or the transaction hangs); `#mesh` exports `transaction(fn)` with the same rule: it takes no context, hands `fn` nothing, opens on the binding in scope (else the connected one) or joins the running transaction, and stays an outermost transaction for the seams (TXN-14). `input`, `before` and related records are `DeepReadonly` in the generated scope types (`<Entity>Loaded` is `self`), and `structuredClone` there is `cloneValue`, which returns a plain mutable copy. A computed field that calls `privileged` or an entity's action is `MESH_COMPUTED_COMPOSES`. The member passthrough (an omitted input keeps the stored value) applies to the member input `&x` only, never to an argument; `always` blocks run before the action's own, `bind(layer, { clock, seams })` takes the clock `now()` reads and the seams (M6, ADR-0075; `runtime/src/seams.ts`, `MeshConfig.seams`, which `connect()` reads: every generated write action runs inside `$runAction(layer, options.seams, {entity, action}, parsed, context, body)`, which runs `beforeTransaction` only when the call opens the transaction (`layer.refuseIfFailed()` false), collects changes per `DataOperations` object in a WeakMap and takes the list inside the transaction callback (`outermost` in `seams.ts`, also used by the application `transaction`, so a layer that hands every transaction the same operations object cannot mix two calls' changes), records them only when `afterCommit` is registered, and runs `afterCommit` once after the outermost transaction resolves; seams get deeply frozen copies of input, `before` and `after` (a `Date` read-only) and a frozen top-level copy of the context (never cloned or frozen below that: it holds the application's objects); the compiler's config loader accepts `seams` (only the three seam names, each a function); an `afterCommit` throw is `console.error`'d and does not fail the call; a read runs no seam; `mesh explain` prints a `seams` section; the Hyper tests' `world.ts` takes `empty({ seams })` and exports `populate` and `eventOf`), `mesh explain <entity> <action>` prints the plan (`typescript/explain.ts`), with a `policies` section that lists each covering policy and where each check runs; `on:load` is listed in a comment as not run; a read casts its input, then runs its covering policies before the query (`$authorizer(...).filter`, over the parsed input), and returns `[]` when they do not admit the caller; a read no policy covers is `ForbiddenError`; a read policy that reads the record is the build error `MESH_NOT_IMPLEMENTED` naming M10, and a read with its own `filter`/`sort`, which fails naming M10 anyway, skips its policies); what a caller loads (a read's `load`, a write's `load=` step, a nested entity read) runs the read policies of the entity it reaches, actor-only, with the caller's scope (POL-17: each load plan entry carries `reads`, the target's covering read policy specs from `loadPolicies`; the read body takes `policies` and the write's final load passes `{ ...$load, policies: true }` to `loadRows`, which runs `Authorizer.admits` once per target per call): not admitted, a has-many is `[]`, any other relationship `null`, a `count` 0 and any other rollup `null`, and a target no read policy covers gives nothing (an entity with policies, none covering `read`, is the warning `MESH_LOAD_NO_POLICY` at each relationship that reaches it, `model/lifecycle-limits.ts`; one with no policy at all is left out); `loadRows` decides the policies first (`deniedNames`, with `input: {}`) and queries a denied name only when a named computed body reads it (`readByBodies`), so a dangling required belongs-to throws only for an admitted caller; a computed body's own reads are not filtered (POL-19: it is the entity's own rule, as a `privileged` read is); a load target whose read policy reads the record is the M10 build error; so the caller types (`<E>Loadable`, `<E>With`) make every relationship but a has-many `T | null`, while `<E>TxLoadable`/`<E>TxWith` (emitted only for an entity with a required belongs-to; `txLoadTypes`) keep a required belongs-to non-null for `privileged` reads, the read bodies and `load<E>Fields` (whose options are `Omit<LoadOptions, "policies">` and which passes `policies: false`); the read action casts its input once, for its policies, and hands `$parsed` to the read body as `cast` (`CastOutput<S>` from `@meshfw/runtime`), which casts only when it is absent (a `privileged` read); `privileged` reads and loads skip policies; a nested entity call is checked against the nested action's policies with the caller's context, and `ActionContext` has the reserved `system?: boolean` (ADR-0071), which `isSystem(context)` (a registered function) reads, so a project's context declaration is needed for any other key an object literal passes (a weak type: an undeclared key is an excess-property error); a policy that reads `before` is `MESH_POLICY_BEFORE`, one that calls an entity's action is `MESH_POLICY_ACTS`, `actions=` naming no action of the entity is `MESH_UNKNOWN_ACTION` (on `always actions=` too), an empty `actions=[]` is `MESH_MEMBER_REFERENCE`, a registered call such as `isSystem` with the wrong number of arguments is `MESH_EXPR_ARITY`, and a create policy that reads `&x` is the warning `MESH_POLICY_NOT_APPLIED`; an update or destroy of a missing row is `NotFoundError` before any record-reading policy check (POL-18); a policy's functions are `policy.<name>.authorize-if.<i>`, `.forbid-if.<i>` and `.when` in the expressions file; a read takes the caller's `{ filter, sort, limit, offset, load }` (`load` only on an entity with a relationship or a computed field: the function is `<const L extends readonly (keyof <Entity>Loadable)[] = readonly []>` over `Omit<Read<E>Input, "load"> & <E>LoadArg<L>` and returns `<E>With<<E>LoadNames<L>>[]`, so a tuple is inferred with no `as const`, `load` is required when it names something, a widened array (`number extends L["length"]`) names nothing, and the result distributes over `L` (`L extends unknown ? <E>With<<E>LoadNames<L>>[] : never`, likewise in the read-only twin), so a conditional or union-of-tuples list gives a union of results that the caller narrows; an unknown name is a type error and `InvalidInputError` from the validator before any query; the read runs its query, then `loadRows` in the same transaction, a loaded has-many in primary-key order from the data layer's `select` tie order; `bind<Entity>Reads(layer, options)` takes the options (the clock) and the read body takes `(input, context)`, since a load runs computed bodies that read `actor` and `now()`; `privileged` reads call the same bodies with the context they are given and the running action's instant: one action call reads the clock once (`pinClock`, used for the scope's `now()`, `$now`, the `load` step and every `privileged` read, and by `loadRows`/`loadInto` once per call, not per row or field); so `privileged(Task).read({ load: ["derivedState"] })` works in a check; Hyper's `derivedState`, `maxFence` and `inReview` helper copies are gone) (per-entity `<Entity>Filter`/`<Entity>Sort` types; `json` attributes are not filterable), a read that declares its own `filter`/`sort` in the file throws `FrameworkError` naming M10, as does a caller's `filter`/`sort` naming a computed field or rollup (the types and validators accept the names for that reason), and a create fills a `uuid` or `string` key itself when it builds the instance (`$uuidv7()` in its `$changes`, so checks and steps read `&id`), while an `integer` key is left to the data layer (the next integer under `integer-key-fill`) and is null until the write. The scope types say what `self` is where (`views/expressions.ts`): `<E>Scope` (a step), `<E>StoredScope` (an update's or destroy's step: `before` non-null), `<E>CheckScope` (`Omit<<E>Scope, "before">`, a check), `<E>NewScope` (a create's check: the members nothing has filled yet, from `model/new-instance.ts`, are `| null`) and `<E>CreateScope` (a create's step before the write with an `integer` key: the key is `| null`). The diagnostics (`model/check-expressions.ts`, `model/lifecycle-limits.ts`): `before` in a check is the error `MESH_VALIDATE_BEFORE`, and at run time the checks get `checkScope($s)` from `@meshfw/runtime` (the scope without `before`) while the steps keep `$s`; a create's check reading `&x` for a member input `&x`, translated or plain, is the warning `MESH_VALIDATE_NOT_APPLIED` (the fallback of `input.x ?? &x` is exempt: the `??` right-hand edit carries `fallback: true`; a warning because a check that also runs on updates may mean the stored value, where `input.x ?? &x` would change its meaning); an operator over a required member a create's check sees unfilled is the warning `MESH_VALIDATE_UNFILLED`, whose message depends on the part (`that` fails on every create, `when` is skipped on every create, `details` is null). A translated expression reads `undefined` as `null`, so `input.x ?? &x` cannot tell a sent `null` from an omitted field; a rule that must is plain code (`input.x === undefined`). [Entities](./apps/docs/docs/docs/entities.md) is the language reference; [the decision records](./apps/docs/docs/architecture/decisions/0049-vocabulary-is-meshs-own.md), starting at ADR-0049, explain the design.

## Layout

Bun workspace (`workspaces`: `packages/*`, `apps/*`, `examples/*`), one root `bun.lock`.
- `packages/compiler` (`@meshfw/compiler`), three folders under `src/` ([ADR-0076](./apps/docs/docs/architecture/decisions/0076-compiler-front-end-and-back-end-are-separate.md); `test/architecture.test.ts` scans the imports): `front-end/` (MX IR to the model, language-neutral; the only code that imports `@mxlang/*`; `expression.ts` turns a function's Babel node into the expression tree or marks it plain, and reports free variables; a function that names `privileged` or an entity value, or that awaits while it calls an imported function (`awaits-helper`), is plain as a whole without the `MESH_EXPR_PLAIN` warning, since an expression helper must be synchronous): closed v4 MX contracts (`contracts.ts`), Mesh's dialect (`dialect.ts`, the frozen `MESH_DIALECT`), the entity file extension list (`extensions.ts`, `MESH_EXTENSIONS`; nothing else spells `.mesh.mx`), the IR reader (`tree.ts`), the entity builder (`build.ts`; an entity names its own type with no import; a `json` attribute or argument is always `nullable` in the model, since it validates only that the value is JSON and `null` is JSON (ENT-03, ADR-0069), so a `nullable` written on it warns `MESH_JSON_NULLABLE`; the read inputs `filter` and `sort` are not attributes and still reject `null`) and `relationships.ts` (after all entities are built: a `belongs-to` gets `keyType`, the type of its target's key, a `has-many`/`has-one` gets `inverse`, the `belongs-to` of the target it follows, from `inverse=:name`, else the only candidate, else the one named after the entity in lower camel case (DOM-32); several candidates with none so named, or an `inverse=` that names no `belongs-to` back, is an error; no `belongs-to` back is not, it fails when loaded); `model/`: `BuildResult`, `ProjectDescription`, how a diagnostic is made, `checkExpressions` (types every tree across the model, warns, demotes to plain; the model itself is `@meshfw/model`) and `computeNeeds` (`Computed.needs`: the relationship and computed paths a body reads, so loading it loads them first; a plain body gives only the `&names` it reads; computed fields that read each other are an error; a plain body's `&name?.a?.b` chain is followed). `front-end/rollups.ts` also makes what is known to fail at load a build error: `sum`/`avg`/`min`, a rollup over a join (M10), a relationship with no `belongs-to` back that a rollup or computed field reads; `typescript/` (the back end; reads the model only, never imports `front-end/` or `@mxlang`): the generators (views in `typescript/views/`, plain data whose types are exported from the index and are the contract a project template renders; Jig templates in `typescript/templates/`, which only print view fields with `@if`/`@else`/`@each`/`{{ }}` (a trailing `~` on a tag trims its newline); `typescript/emitters/types.ts`, `validators.ts`, `load.ts`, `actions.ts`, `binding.ts`, `module.ts`, `index.ts`; `renderGenerator` in `typescript/emit.ts`); `config.ts`, `paths.ts` and `index.ts` are the shell that calls both halves and the `model.json` emitter (tests in `test/`). Generated code imports only `@meshfw/runtime`, `zod`, the other files of its `.mesh/` tree, the adapter's `schema.ts` and, in `binding.ts` only, the project's `mesh.config.ts` (`connect()` imports it dynamically) and `node:async_hooks` (the project's async frame) (`checkGeneratedImports` in `test/repository-checks.ts`, which also fails any other generated file that imports a path ending in `mesh.config` or `node:async_hooks`, and any generated file that imports another `node:` or `bun:` module); the actions file reaches a table as `tables.<stored table name>` (`tableAccess` in `views/actions.ts`; `tables` is keyed by table name, and the adapter's `schema.ts` exports only `tables`). `parseEntitySource` in `front-end/build.ts` is the one MX call (`lowerSource` from `@mxlang/core`, called with the options below): contracts, `dialect: MESH_DIALECT` (which carries `tagRules: "none"`; the compiler passes no `tagRules`), `structural`/`unknownTags: "reject"`, `imports: "pass"`; the test helper and the docs checks use it too (two unit tests, `test/syntax.test.ts` and `test/tree.test.ts`, call `lowerSource` with only `MESH_DIALECT` on purpose, to pin the lowered shapes without contracts)
- `packages/model` (`@meshfw/model`): plain-data entity model, eleven attribute types and four action types, diagnostic types, the expression tree (`ExprNode`) and the function registry (`FUNCTIONS`); imports nothing
- `packages/runtime` (`@meshfw/runtime`): the in-memory expression functions (`expr`, `scope`, `Clock`; ADR-0012 option A: unknown is `null`, tables in `@meshfw/runtime/testing` `EXPRESSION_TABLES`), flat, project-augmented `ActionContext` and `ContextArgument` (the generated action's `...[context]` rest tuple, optional until a required key is merged), errors, entity values and bindings (`entity.ts`: `entity`, `bindDomain`, `bindingInScope`, `connectBinding`, `releaseBinding`, `settled`, `Binding`, and `AsyncFrame`, the async context it takes from the generated `binding.ts`), Standard Schema input validation, `loadRows` (M7: relationships by a second query for all the rows in chunks of 500 keys, a computed body after what it reads, `count`/`max` rollups through the data layer once per row, or from the rows when the same call loaded the has-many; a plain computed body gets a guarded record that throws on a relationship or computed field that was not loaded; a plain load plan, no knowledge of a database) and `rejectComputedQuery`, `DataAdapter` descriptors (with `build`, the adapter's build-half specifier), `defineConfig`/`MeshConfig` (here so a config imported at run time loads no compiler code) and data-layer contract v1; zero run-time dependencies; adapter conformance checks at `@meshfw/runtime/testing`
- `packages/data-drizzle` (`@meshfw/data-drizzle`, private): `drizzleOperations(commands, guard)`, contract v1 over a Drizzle table, shared by SQL adapters; depends on `@meshfw/runtime` and `drizzle-orm` only
- `packages/data-sqlite` (`@meshfw/data-sqlite`, private), two entries. Main (`src/index.ts`, run time; imports no model, compiler or drizzle-kit): `sqlite({ file })` returns one frozen value that is the `DataAdapter` descriptor and a lazily opened `DataLayer` (Mesh's own queued `BEGIN IMMEDIATE` transactions, `src/layer.ts`; `close()` returns it to unopened, so the next transaction reopens the same file and `disconnect()`/`connect()` reuse the configured layer), and `createSchema(db, tables)`. `./build` (`src/front-end/build.ts`, build time): the `AdapterBuild` whose `sqlite-schema` generator (`schemaView` + `templates/schema.ts.jig`) writes `.mesh/schema.ts`, and whose `db push` command backs `mesh db push`. `src/push-schema.ts` (`planSchemaPush`) is the one place that imports `drizzle-kit/api`, dynamically; `src/identifiers.ts` refuses backticks and control characters in names before any DDL. Its tests call actions through `callsOf(binding, domain)` (`test/calls.ts`), which runs `<Entity>.<action>` inside `binding.run` under the `<action><Entity>` name, since they pin what an action does, not how it is called
- `packages/cli` (`meshfw`): the Bun-only `mesh` developer command, a thin compiler shell; re-exports `defineConfig` from `@meshfw/runtime` (not the compiler) for compatibility, but a project's `mesh.config.ts` imports it from `@meshfw/runtime` (ruled in the PR #54 review: `connect()` loads the config at run time and `meshfw` is a dev dependency); runs the data adapter's commands (`mesh db push`) after the guard, with no adapter-specific code
- `packages/create-meshfw` (`create-meshfw`, public): the starter behind `bun create meshfw`; today a placeholder bin that prints "Mesh is coming soon" and the site URL, published by the operator to reserve the name
- `apps/docs`: the docs site (docmd)

## Commands

- MX is a separate project, published on `https://npm.saulo.tech`; the root `bunfig.toml` scopes `@mxlang` to that registry and `packages/compiler` depends on `@mxlang/core` by exact version (currently `0.1.0-alpha.22`; `@mxlang/data` no longer exists and `@meshfw/compiler`'s `package.json` has no `mx` key; `@mxlang/tree-sitter-mx` stays at `0.1.0-alpha.2`). `lowerSource` returns `{ ir, diagnostics }` (IR version 3, `ir` undefined on any error, never throws). A tag is a `DelegatedTag` node; an attribute is `static` (string, atom or member, told apart by `atom` and `member`), `boolean`, `dynamic`, `bound` or `spread`; a tagless member line is a `member` tag with `trigger.id === "member"`. Imports are `ir.imports` (`from`, `names`, name `span`/`localSpan`). `src/front-end/dialect.ts` builds `MESH_DIALECT` from Mesh's own syntax rows in `src/front-end/syntax/` (`atoms-sugars.ts`, `member.ts`, `mesh.ts`, ported from MX's reference module at MX commit `750c80ec1`; MX deletes its copies after Mesh sends DONE; Mesh owns all of its syntax): id `mesh`, name `Mesh`, `tagRules: "none"`, no `#id`/`.class` rows. The dialect also carries Mesh's vocabulary and its strictness (since MX alpha.21): `contracts: MESH_CONTRACTS` (`Dialect.contracts` is `@unstable` in MX), `structural: "reject"`, `unknownTags: "reject"`, `imports: "pass"`. A caller of `lowerSource` passes the dialect and nothing else, never `customTags` (a passed `customTags` overrides the dialect's `contracts` silently) and no strictness option, so the editor checks a Mesh file exactly as the CLI does. Build `MESH_DIALECT` once and freeze it: MX re-validates an unfrozen dialect object on every call (about 46 ms instead of 3 ms). A test of the syntax alone uses `SYNTAX_DIALECT` (`test/syntax-dialect.ts`), the dialect without contracts or strictness. The syntax files import only the public `@mxlang/core` API, and `test/no-core-syntax-import.test.ts` fails on any import of `@mxlang/core/syntax` in `packages/` or `examples/`. The value row `atom-value` and the `Atom` node type name the dialect, so the id must stay `mesh`; a whole-value atom (`inverse=:owner`) lowers to the same atom-marked `static` attribute as an atom elsewhere (`Attr.node` stays unset). The atom contract checks are Mesh's (`atomsHooks.afterLower` in `syntax/atoms-sugars.ts`) and see value atoms (`test/atom-values.test.ts`); since alpha.17 core has no name sugar or atom lexing (`:x` in a `.mx` file is plain JavaScript; a dialect row returns a `StringLiteral` marked `extra.mxAtom`) and ships no dialect: a colon in a tag head is part of the tag name (`uuid:id`, `<string:title/>`, `entity:Todo`, `<:x/>` are unknown tags to MX), and an `afterLower` hook sees only the tags a contract names, so the dialect's `explainUnknownTag` hook (`front-end/dialect.ts`; `@unstable` in MX) refuses a name with a `:` as `MESH_UNSPACED_NAME`, replacing MX's own unknown-tag error for it (one lowering; the `:x` wording reads the parent contract's `defaultTag` from the hook's ancestors). Core no longer checks the atom contract keys: `values`, `pattern`, `ref` and `declares` are claimed by Mesh's `contractFields` and checked in its `checkContract`/`afterLower`. `run [after=:write] (...) {}` lowers to one `value`; a real duplicate warns with code `MX_DUPLICATE_ATTRIBUTE`. Match diagnostics by `code`, never by message text: MX's codes are `MX_UNKNOWN_TAG`, `MX_TAG_NOT_ALLOWED`, `MX_TEXT_NOT_ALLOWED`, `MX_EXPECTED_SINGLE_EXPRESSION`, `MX_DUPLICATE_ATTRIBUTE`; Mesh's own come through `ctx.fail(message, { at, code: "MESH_X" })` (never a `MESH_X: ` message prefix), and `buildModel` maps any diagnostic without a `MESH_` code to `MESH_SYNTAX`. Under `unknownTags: "reject"` an unknown tag in a closed parent gives only `MX_UNKNOWN_TAG`; the by-text pair filter is gone. An unnamed tag in a closed parent takes the nearest parent contract's `defaultTag`, so `<set><#a/></set>` gives one error. A spaced `#id`/`.class` is Marko's "Invalid attribute name"; `<x=1 :n=2/>` is Marko's "Expected a single expression, but found `:` after it." (`MX_EXPECTED_SINGLE_EXPRESSION`). Members are read from those shapes only, never from `Expr.code` (printed `self.x`); authored text is the source sliced at `Expr.span`. `meshfw`'s package.json declares `mx.dialect` (`id: "mesh"`, `extensions` equal to `MESH_EXTENSIONS`, `module: "./dist/dialect.js"`); `bun run build` in `packages/cli` (`scripts/build-dialect.ts`, part of `verify`) bundles `src/dialect.ts` into that plain-JavaScript file, fails when the manifest drifts from `MESH_EXTENSIONS`, and `packages/cli/dist/` is gitignored. `prepare` runs the same build, so `bun install` and `bun pm pack` produce `dist/`. MX loads the module in whatever runtime hosts it (Bun in Mesh's tests) and the file must be JavaScript Node can also load, so the module can never be `.ts`; `@meshfw/compiler` exports `./extensions` (the extension list) for the build script, so installing does not load the whole compiler. The manifest also sets `mxConfigTags: false` (Mesh files take nothing from the project's `mx.tags` or `mx.contracts`), `tagDirs: []` (MX's generic `tags/` directory is closed to them) and `reservedTags` (every key of `MESH_CONTRACTS`, so a project definition of one is `MX_RESERVED_TAG`; `test/dialect-registration.test.ts` fails when the list and the contracts differ). Concepts (ADR-0085) will need a declared `tagDirs` entry later. `bun install` at the repo root is all there is: no `bun link`, no token, no local MX checkout. `bun run verify` runs on GitHub Actions (`.github/workflows/verify.yml`) on every pull request and every push to `main`. To work against an unreleased MX commit, run `bun link` inside the MX checkout and temporarily point `packages/compiler`'s two `@mxlang` dependencies at `link:` (or at a `file:` path), then revert before committing; never commit a `link:` entry, and never run `bun link @mxlang/...` at the root, which writes a `link:` dependency into the root `package.json`.
- Jig: `@jig-lang/jig` is pinned exact (`1.0.1`, from npm) as a dependency of `@meshfw/compiler` only; `src/typescript/render.ts` is its one import site (a test enforces it; runtime, model, the CLI and generated code never import it). Jig's disk loader resolves `.edge` only, so Mesh reads each `*.ts.jig` file itself and renders with `await edge.renderRaw(contents, view, templatePath)` (`templatePath` is only what errors name; do not use `renderRawSync`, whose wrapper has the wrong signature). `{{ }}` does not escape, and the final newline is dropped (Prettier restores it). ## Rules

- The user-facing CLI package is `meshfw` (binary `mesh`; it re-exports `defineConfig`, but projects import `defineConfig` from `@meshfw/runtime`); the starter is `create-meshfw` (`bun create meshfw todo-app`). Other framework packages remain `@meshfw/*`. These are the workspace package names and the documented 1.0 naming. User docs write `mesh build` and other `mesh` commands; Quick start alone explains the `bunx mesh build` local-binary alternative.
- User docs separate `configuration.md` (project/context/adapters/environment) from `command-line.md` (commands/flags/exit codes). `using-your-domain.md` replaces the old Calling actions page. Framework integration snippets are explicitly `(excerpt)` fences; the sample checker counts exclusions dynamically rather than claiming they compile.
- `plugins/mx-figure.js` also injects site title/heading CSS and strips paired code backticks from docmd's known plain-text title labels at build time. It must not rewrite authored code blocks, URLs or escaping. `apps/docs/test/browser/docs-structure.mjs` checks the sidebar/home link, heading scale and title labels in both themes; it needs `SHOTS_DIR`, `SITE_DIR` and `PLAYWRIGHT_MODULE` (Playwright Docker), separately from `verify`.
- `typescript` and `@types/bun` are declared only in the root `package.json`; packages do not repeat them.
- Use bun, never npm.
- Always write "Mesh" (never "Mash").
- Architecture docs hold what cannot be understood from a single code file.
- The `@mxlang` scope resolves from `https://npm.saulo.tech`, the operator's read-only npm registry (no uplink);
  `bunfig.toml` points only that scope at it. `@mxlang/tree-sitter-mx` is what the docs site highlights `mx`
  with; a docs fix goes in `apps/docs/plugins/mx-highlight.js` (the docmd plugin, the capture-name palette)
  or goes to the MX lead as a grammar gap.
- `apps/docs/plugins/mx-highlight.js` is MX's highlighter's docmd plugin and not ours to fork: the grammar
  and the queries belong to MX. Change the palette only, except for the explicitly approved, tested,
  counted v4 input allowance above and `MESH_V4_MEMBER_RENDER`: a Mesh-side render-only overlay
  that colours operand/bare/sort `&name` heads as `ts-member`, leaving literals, comments and infix
  operators alone. Both bridges go away with `mesh-syntax-highlighting-route` (MX decision 182
  addendum 1). Do not patch the grammar or broaden either bridge silently.
- Home token explanations live in `apps/docs/plugins/mesh-home-hints.js`, wired by `mesh-home.js`.
  Keep descriptions outside the code so copying and the home-sample hash retain the authored file;
  every token in the fixed excerpt is checked against the commissioned wording. Each note has a shared
  family sentence followed by optional context; inline fragments use `mxHighlighter` at build time
  (TypeScript through its injection grammar), never a browser highlighter. Reference tokens name
  scoped targets for a single dashed SVG connector and outline. Keyboard navigation has one tab stop
  per nonblank line, with Left/Right and Home/End within it. Mutation/resize observers run only while
  a note is open; the panel is re-created after body replacement. Browser interactions and screenshots
  are exercised by `apps/docs/test/browser/home-hints.mjs` in Playwright's Docker image, separately
  from `bun run verify` (see the script header for its environment variables; screenshots default
  under `os.tmpdir()`, not the checkout).
- docmd 0.9.7 reads a raw HTML block until its tags balance, blank lines included, so Markdown (a fence
  above all) inside an open `<div>` is emitted as raw text. Wrap fences in a docmd container (`::: grids`)
  instead, and keep each HTML block self-contained. docmd also hides `<html>` until its theme script runs;
  `plugins/mx-figure.js` adds the `<noscript>` rule that keeps the site readable without JavaScript.
